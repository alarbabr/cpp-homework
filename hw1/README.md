# ДЗ 1 — merge sort для int и Point

Реализация основана на коде, который студент написал в ходе разбора задания. `mySort` копирует заданный диапазон во временный вектор, вызывает собственную рекурсивную сортировку слиянием и записывает результат обратно. `std::sort` внутри реализации не используется.

## Запуск в Windows / MSVC

Нужны Visual Studio с компонентами C++, CMake и AddressSanitizer. Откройте **x64 Native Tools Command Prompt for Visual Studio**, перейдите в корень проекта и выполните:

```bat
hw1\run_windows.cmd
```

Скрипт останавливается при ошибке сборки или провале теста. Он сначала запускает Debug-тесты, затем Release-замеры. Таблица печатается в консоль и сохраняется в `hw1/results/bench_windows.csv`.

Те же действия вручную из корня проекта:

```bat
cmake -S hw1 -B build-debug -DHW1_BUILD_TESTS=ON -DHW1_BUILD_BENCH=OFF -DCMAKE_BUILD_TYPE=Debug
cmake --build build-debug --config Debug --target hw1_tests
ctest --test-dir build-debug -C Debug -V --output-on-failure

cmake -S hw1 -B build-release -DHW1_BUILD_TESTS=OFF -DHW1_BUILD_BENCH=ON -DCMAKE_BUILD_TYPE=Release
cmake --build build-release --config Release --target hw1_bench
build-release\Release\hw1_bench.exe hw1\results\bench_windows.csv
```

Последняя команда предполагает генератор Visual Studio. При генераторе Ninja исполняемый файл находится в `build-release\hw1_bench.exe`; скрипт учитывает оба расположения.

В Debug для MSVC добавляется `/fsanitize=address`, отключаются несовместимые `/RTC` и инкрементальная линковка. В Release benchmark собирается с `/O2` без добавления флагов санитайзеров. Это отдельные каталоги и отдельные цели сборки.

## Запуск в Linux / GCC или Clang

```sh
cmake -S hw1 -B build-debug -DCMAKE_BUILD_TYPE=Debug -DHW1_BUILD_TESTS=ON -DHW1_BUILD_BENCH=OFF
cmake --build build-debug --target hw1_tests
ctest --test-dir build-debug -V --output-on-failure

cmake -S hw1 -B build-release -DCMAKE_BUILD_TYPE=Release -DHW1_BUILD_TESTS=OFF -DHW1_BUILD_BENCH=ON
cmake --build build-release --target hw1_bench
./build-release/hw1_bench hw1/results/bench_local.csv
```

В Linux Debug использует `-fsanitize=address,undefined`; Release — `-O2`. Это переносимые аналоги настройки для локальной проверки. Актуальный запуск на этом компьютере с MSVC описан в [results/WINDOWS_RUN_REPORT.md](results/WINDOWS_RUN_REPORT.md); прежние измерения на Linux-сервере сохранены в [results/RUN_REPORT.md](results/RUN_REPORT.md). Перед защитой можно повторить замеры, поскольку время зависит от текущей нагрузки компьютера.

## Что проверяют тесты

Для обоих типов: пустой вектор, один элемент, отсортированные данные, обратный порядок, все элементы равны, повторяющиеся элементы, случайные данные размеров 10, 1000 и 100000 с двумя фиксированными seed. Дополнительно проверяются отрицательные числа, пределы `int`, убывающий компаратор, компаратор по умолчанию, обычный `int[]` и часть вектора. Для точек есть отрицательные координаты и разные точки с одинаковым расстоянием.

Каждый обычный тест проверяет:

1. Порядок через `std::is_sorted` с тем же компаратором.
2. Сохранность элементов, включая число повторений, через сравнение независимо упорядоченных копий.

Для точек сохранность проверяется по координатам. Сравнивать два результата поэлементно после сортировки только по расстоянию было бы неверно: порядок различных равноудалённых точек может отличаться.

`require` выбрасывает исключение при провале проверки, программа печатает причину и возвращает код 1. Для успешного запуска код возврата равен 0. Поэтому CTest различает успех и провал автоматически. Проверки не зависят от `assert`.

## Методика замеров

Размеры случайных входов: 1000, 10000, 100000, 1000000 отдельно для `int` и `Point`. Для каждого алгоритма используются копии одинаковых исходных данных. Данные генерируются и копируются до запуска таймера. Измеряется весь вызов сортировки, включая внутренние выделения памяти `mySort`.

Для каждого алгоритма выполняется один прогревочный запуск и пять измерений. Итог — медиана пяти времён. Порядок запуска алгоритмов чередуется. Используется `std::chrono::steady_clock`, время выводится в миллисекундах. Проверка порядка и вывод результата находятся вне измеряемого участка.

Дополнительно замеряются уже отсортированные данные размера 100000 для обоих типов. Программа печатает `mySort(sorted) / mySort(random)` для одинакового размера. Сортировка слиянием не выбирает опорный элемент и сохраняет O(n log n) на таком входе.

Ожидаются 10 строк в основной таблице: 8 случайных входов и 2 отсортированных. Колонка `my/std` — отношение времени `mySort` к `std::sort`; значение больше 1 означает, что `mySort` медленнее. Фиксированный seed воспроизводит вход внутри той же реализации стандартной библиотеки; разные библиотеки могут давать разные последовательности распределения.

## Сложность и свойства

Время — O(n log n) в худшем и среднем случае; дополнительная память — O(n), стек рекурсии — O(log n). Обёртка добавляет O(n) работы и O(n) памяти, поэтому итоговые оценки сохраняются. Эта учебная реализация создаёт много временных векторов, что увеличивает константу времени. Устойчивость не гарантируется: при эквивалентных элементах слияние выбирает правый.

Тестовые координаты конечные и ограничены по модулю 1000; сравнивается `x*x + y*y`. Квадратный корень не нужен, поскольку он сохраняет порядок неотрицательных величин.
